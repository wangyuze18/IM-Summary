# 前端设计文档：可比较的双任务工作台

## 1. 产品目标

前端让研究者或业务用户在同一会话上切换基础模式与团队模式，观察运行过程、阅读统一简报并比较六项评测指标。界面应解释“正在做什么”，但不展示实验实现口号或多余状态标签。

## 2. 信息架构

```text
窗口标题栏
├─ 会话侧栏：导入、搜索、会话列表、删除
└─ 主工作区
   ├─ 模式切换与运行计时
   ├─ 工作流动画
   ├─ 原始消息 / 群组上下文
   ├─ 生成结果 / 黄金结果
   └─ 六指标概览 / 评测历史
```

系统没有登录账户语义。群组上下文展示成员与关系图；关系图中心按结构连接度选择，不标识“当前用户”或“与我相关”。

## 3. 数据原则

所有业务数据来自后端：会话、消息、成员、关系、模型配置、摘要、运行与评测。前端启动时探测 `VITE_API_BASE_URL`，探测失败则清空业务区域并提示连接后端。

禁止：

- 内置 mock 会话或摘要；
- 离线计时模拟 Agent 完成；
- 本地伪造导入、模型保存或连接测试成功；
- 在后端失败时展示上一次 mock 数据。

## 4. 模式交互

模式切换器只显示“团队模式”和“基础模式”。悬停说明简洁描述差异；分析过程中禁用切换。右侧仅显示当前运行计时或该模式上次真实运行耗时。

不展示“未审核 baseline”“审核通过”“双审核通过”等标签，因为这些文字没有帮助用户理解具体内容。团队模式的详细证据与问题放在结果区的“质量详情”折叠面板中。

## 5. 卡通工作流视觉

主图与运行素材采用同一套 ACL 论文卡通机器人视觉语言。`acl-robot-agents-sprite.png` 是 4×2 角色图集：事件研究员、状态专员、摘要撰稿人、消息分析员、摘要审核员、消息审核员，以及基础模式的两个机器人。

### 5.1 基础模式

“摘要生成”和“重要消息”并列一行。运行时两个机器人同时浮动并发光，状态来自后端的真实步骤。

### 5.2 团队模式

图形结构必须与真实编排一致，但不采用人物悬挂在树线上的大画布。团队模式使用“双轨编辑台”：事件识别 → 状态判断构成共同理解区；随后分入摘要和重要消息两条等高泳道，每条泳道都在内部完整呈现“生成 → 审核 → 未通过时返回修订”的闭环；两条泳道最终汇入工作简报。所有角色使用统一尺寸的横向机器人胶囊，连接关系由同一 SVG 坐标系连续绘制。团队与基础模式保持接近的面板高度，团队泳道在可用宽度内舒展排布。

动画规则：

- running：机器人轻微浮动、边框呼吸；
- revising：对应机器人执行短距离定向移动；
- connector active：连接线上出现沿路径移动的信号；
- completed：保留稳定的完成色，不持续闪烁；
- `prefers-reduced-motion` 开启时应停用非必要动画。

动画只作用于卡通机器人和信息流，不混用通用旋转图标作为 Agent 形象。

## 6. 模型设置

入口名称固定为“模型设置”。抽屉内部按用户意图分为两块：先在“可用模型”中添加、验证和选择常用模型，再在“工作分配”中切换基础模式、团队模式或结果评审，为每项工作选模型。添加模型时，用户填写服务地址与访问密钥，界面自动加载可选模型；选中模型后自动识别思考模式能力，支持时再由用户决定是否开启。结果评审使用加宽的单卡布局。用途由角色卡片的名称、动作和机器人形象直接表达，不展示凭据传输、共享绑定或指标实现等工程说明。

基础模式使用同一行的两张卡片：

| 摘要生成 | 重要消息 |
| :--- | :--- |
| 从原始群聊生成摘要 | 从原始群聊抽取消息 |

`importance-extractor` 由两种模式共用，保证评测对比的模型条件一致。评测判分模型独立设置，说明 `llm_score` 只评价摘要。

## 7. 结果区

生成结果与黄金结果并列。Markdown 使用 GFM 渲染。统一简报中的“重要消息”位于“摘要”下方，按 stakeholder 分组。

页面不添加装饰性表情；后端渲染器也做最终清理。不存在个人关注项。团队结果可展开质量详情，查看事件数、证据关联数以及两个审核器的具体问题，不用一句“通过”口号代替证据。

## 8. 评测区

标题为“评测指标”。六个卡片在桌面宽度同一行：

1. 摘要准确率；
2. 关键信息遗漏率；
3. 文本相似度；
4. 大模型文本评分；
5. 重要消息精确率；
6. 重要消息召回率。

下方历史表格同步展示六项，可按模式筛选，并导出 CSV、JSON 或 Markdown。重要消息黄金标注缺失时显示“暂无标注”，不显示 0 分以免误导。

## 9. 响应式布局

- 宽屏：六指标同一行，摘要与黄金结果双列；
- 中等宽度：保留工作流关系，指标允许横向滚动，避免压缩成不可读小卡；
- 窄屏：内容区单列，机器人节点适度缩小；
- 表格使用独立滚动容器，不截断表头。
- 滚动条默认保持低对比和窄尺寸，仅在悬停或聚焦滚动区域时增强可见度。

## 10. 可访问性

- 模式按钮使用 tab 语义和 `aria-selected`；
- 机器人 sprite 提供角色 `aria-label`；
- 颜色以外仍提供状态文字；
- 模态框支持明确关闭按钮；
- 动画遵守 reduced motion 偏好；
- 重要信息不只依赖红/绿颜色表达。

## 11. 验收清单

- 无后端时不出现示例业务数据；
- 模式卡片和设置文案无 baseline/双审核等冗余口号；
- 两种模式均使用同风格机器人；
- 动画由后端状态驱动；
- 摘要下方能看到重要消息；
- 没有个人账户/个人关注视图；
- 六项指标同一行且历史表格完整；
- `npm run typecheck` 与 `npm run build` 通过。
