# 摘要 JSON → Markdown 渲染规范

## 版本: V1.1
## 日期: 2026-08-27
## 适用范围: 两种分析模式的 SummaryResult 渲染、黄金摘要渲染、Markdown 导出

> V1.1 变更（2026-08-27）：
> 1. 移除 `personalHighlights`（与我相关的重点/个人关注项）小节及字段；
> 2. 小节标题不再携带表情符号（原 ❗/📋/💬/❓/🎯 全部去除），保持纯文本标题；
> 3. 黄金摘要（数据集 groundTruth.goldenSummary）与智能摘要**共用同一渲染模式**，便于人工对照；
> 4. "单模型基础模式"更名为"单模型"。

---

## 1. 总体原则

1. **统一渲染**：agent-workflow 与 single-model 模式产出相同结构的 SummaryResult，使用同一套渲染规则；黄金摘要导入时同样经本规范渲染（分析模式标注为"黄金摘要（人工参考）"），保证导出格式一致、便于人工对比。
2. **空节省略**：某字段数组为空时，该小节整体省略（不显示空表格/空列表）。
3. **实体保真**：@提及、人名、版本号、系统名原样保留。
4. **标题纯文本**：所有小节标题不使用表情符号。
5. **渲染时机**：
   - 后端在固化 SummaryResult 时生成 `markdown` 字段（导出接口直接使用）
   - 黄金摘要在导入确认时渲染并持久化
   - 前端展示时也可直接渲染该字段

---

## 2. 标准模板

```markdown
# 工作群聊分析简报
**群组名称:** {groupName}
**报告周期:** {period}
**分析模式:** {Agent 团队模式 | 单模型 | 黄金摘要（人工参考）}

---

### 摘要
* {abstractPoint1}
* {abstractPoint2}
* {abstractPoint3}

---

### 决议事项
* **决议{N}:** {title}
  * **背景/上下文:** {context}
  * **状态:** {status}

---

### 待办事项

| 优先级 | 任务内容 | 负责人 | 截止日期 | 状态 |
| :--- | :--- | :--- | :--- | :--- |
| {priority} | {task} | {owner} | {dueDate} | {status} |

---

### 主要议题讨论
**议题 {N}: {title}**
* **时间段:** {timeRange}
* **主要参与者:** {participants}
* **过程概述:** {process}
* **核心结论:** {conclusion}

---

### 待解决问题与关键信息
* **待解决问题:**
  1. {openIssue1}
  2. {openIssue2}
* **关键信息/文件:**
  1. {keyInfo1}
  2. {keyInfo2}
```

## 3. 字段渲染规则

| JSON 字段 | 渲染规则 |
|-----------|----------|
| `groupName` | 缺失时显示"[未提供]" |
| `period` | 缺失时从消息时间推断；仍无法推断则显示"[未提供]" |
| `abstractPoints` | 无序列表，每条一行 |
| `decisions[]` | 有序编号"决议N"；`context` 为空时该行省略 |
| `todos[]` | 表格渲染；`owner`/`dueDate` 未明确时显示"待明确" |
| `topics[]` | "议题 N: title"加粗标题 + 四项子字段列表 |
| `openIssues` | 有序列表 |
| `keyInfo` | 有序列表 |
| `evidenceLinks[]` | **导出时可选追加**"证据引用"附录小节（仅 Agent 团队模式有值） |

> `personalHighlights` 字段自 V1.1 起不再输出与渲染；历史数据中若携带该字段，渲染时忽略。

## 4. 相对参考样式的优化点

在用户提供的参考样式基础上，做以下优化：

1. **新增"分析模式"标注**：头部标注当前摘要来源模式（Agent 团队模式 / 单模型 / 黄金摘要（人工参考）），导出后人工对比时可直接区分。
2. **黄金摘要同模式渲染**：数据集携带的结构化黄金摘要经本规范同一渲染器输出，与智能摘要版式完全一致，便于逐项人工对照。
3. **标题无表情符号**：小节标题保持纯文本，避免渲染与复制导出时的符号噪音。
4. **证据引用附录（可选）**：Agent 团队模式导出时，可在文末追加证据小节：

```markdown
---

### 证据引用（仅 Agent 团队模式）
| 摘要结论 | 来源消息 |
| :--- | :--- |
| {summaryPoint} | {messageId1}, {messageId2} |
```

5. **空值统一措辞**：负责人/截止日期缺失统一显示"待明确"（与参考样式一致），不使用"未明确"与"待明确"混用。
6. **分隔线统一**：每个一级小节之间使用 `---`，小节内部不使用分隔线。

---

## 5. 导出接口行为

| 导出格式 | 内容 |
|----------|------|
| Markdown | 按本规范渲染的完整简报（可选包含证据附录） |
| JSON | SummaryResult 原始结构化数据 |

导出文件名建议：`{群名}_摘要_{模式}_{版本}.md`，如 `研发群_摘要_单模型_v2.md`。

## 6. 工作简报与重要消息

`abstractPoints` 之后渲染 `### 工作简报`，其下固定使用 `#### 重要消息（按相关人员划分）`。按 `stakeholders` 数组分组，每条显示 `[类型 / 优先级] 说话者: 原文` 及一句重要原因。同一消息影响多个角色时复制到各分组；数组为空则整节省略。

## 7. V1.2 渲染硬约束

- 所有标题和字段在最终输出层移除 ⭐、❗、📋、💬、❓、🎯 等装饰性表情，旧版本结构化结果也适用。
- 永久忽略 `personalHighlights`，即使历史结果仍携带该字段也不得渲染。
- `importantMessages` 同时兼容包装对象、顶层数组，以及 `important_messages/messages/items` 别名；归一化后再渲染，避免模型数组直出导致工作简报消失。
- 模式显示名称统一为“团队模式”和“基础模式”，后端兼容值仍保持 `agent-workflow` 与 `single-model`。
