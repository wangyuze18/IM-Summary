# Markdown 渲染规范

## 1. 固定结构

```markdown
# 工作群聊分析简报
**群组名称:** 群名
**报告周期:** 起止日期

---

### 摘要
- 核心进展

---

### 决议事项
...

### 待办事项
| 优先级 | 任务内容 | 负责人 | 截止日期 | 状态 |
...

### 主要议题讨论
...

### 待解决问题与关键信息
...

---

### 重要消息
#### 张三
* 原始消息内容
  - 重要原因：影响发布
```

重要消息固定为整份 Markdown 的最后一个三级标题，不参与摘要的 `llm_score`。

## 2. 重要消息分组

渲染器按 `speaker` 的人物本名分组，标题不添加 `@`、职位或角色。组内只展示 `content` 和 `reason`，不展示类型、优先级或受影响人。

`content` 使用清洗 HTML 后的原文，不进行二次摘要。链接、命令、版本号与 `@` 提及原样保留。

## 3. 摘要主体

- 摘要固定三条目标，但证据不足时不补造；
- 决议与待办分开；
- 待办用 GFM 表格；
- 议题使用标题加时间、参与者、过程、结论；
- 空数组对应小节可省略明细，但结构化 JSON 不省略字段。

## 4. 字符清理

最终 Markdown 移除装饰性 Unicode 表情及 variation selector，例如星形、感叹图标、剪贴板、对话气泡和靶心。清理同时适用于模型生成内容、群名和标题。

不得删除：

- `@姓名`；
- Markdown 链接与 URL；
- 版本号、代码、命令；
- 中文标点和业务符号。

界面层不额外插入装饰性表情。关闭、勾选等必要控件符号不属于生成简报内容。

## 5. 禁止字段

结果不定义、不渲染账户个人或个人关注小节。黄金重要消息若包含 `type`、`priority` 或 `stakeholders`，导入预检直接失败；模型输出中的额外字段会在持久化前被剔除。

## 6. JSON 契约

```json
{
  "groupName":"string",
  "period":"string",
  "abstractPoints":[],
  "decisions":[],
  "todos":[],
  "topics":[],
  "openIssues":[],
  "keyInfo":[],
  "importantMessages":[{
    "messageId":"m01",
    "speaker":"张三",
    "content":"原始消息",
    "reason":"重要原因"
  }]
}
```

缺失字段在规范化阶段补为空数组或空字符串，不省略顶层键。
