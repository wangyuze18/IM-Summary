# Markdown 渲染规范

## 1. 固定结构

```markdown
# 工作群聊分析简报
**群组名称:** 群名
**报告周期:** 起止日期

---

### 摘要
- 核心进展

### 重要事项
#### @张三
* [阻断 / 高] **@李四:** 原始消息内容
  - 重要原因：影响发布

---

### 决议事项
...

### 待办事项
| 优先级 | 任务内容 | 负责人 | 截止日期 | 状态 |
...

### 主要议题讨论
...

### 待解决问题与关键信息
...
```

重要事项位置固定在摘要之后、决议之前，并使用独立的三级标题。不添加“工作简报”中间标题，也不参与摘要的 `llm_score`。

## 2. 重要消息分组

每条消息可影响多个 stakeholder。渲染器从“开发-@张三”等 stakeholder 中只取 `@员工`建立分组，不把角色前缀带入标题；同一事项影响多人时可出现在多个员工组中。无明确 stakeholder 时按 speaker 归档。组内保留优先级、类型、speaker、content 和 reason。

`content` 使用清洗 HTML 后的原文，不进行二次摘要。链接、命令、版本号与 `@` 提及原样保留。

## 3. 摘要主体

- 摘要固定三条目标，但证据不足时不补造；
- 决议与待办分开；
- 待办用 GFM 表格；
- 议题使用标题加时间、参与者、过程、结论；
- 空数组对应小节可省略明细，但结构化 JSON 不省略字段。

## 4. 字符清理

最终 Markdown 移除装饰性 Unicode 表情及 variation selector，例如星形、感叹图标、剪贴板、对话气泡和靶心。清理同时适用于模型生成内容、群名和标题。

不得删除：

- `@姓名`；
- Markdown 链接与 URL；
- 版本号、代码、命令；
- 中文标点和业务符号。

界面层不额外插入装饰性表情。关闭、勾选等必要控件符号不属于生成简报内容。

## 5. 禁止字段

结果不定义、不渲染账户个人或个人关注小节。导入和评测过程中若输入带有非当前契约字段，只将当前定义的摘要字段和 importantMessages 用于输出。

## 6. JSON 契约

```json
{
  "groupName":"string",
  "period":"string",
  "abstractPoints":[],
  "importantMessages":[],
  "decisions":[],
  "todos":[],
  "topics":[],
  "openIssues":[],
  "keyInfo":[]
}
```

缺失字段在规范化阶段补为空数组或空字符串，不省略顶层键。
