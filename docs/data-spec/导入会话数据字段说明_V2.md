# 导入会话数据字段说明 V2

## 1. 适用范围

本文定义当前 JSON 会话数据集的导入契约。一个文件对应一个群聊会话，顶层由场景元数据、群组、成员、关系、原始消息、人工黄金标注和可选质量审计组成。

当前重要消息契约只有四个字段：`messageId`、`speaker`、`content`、`reason`。`type`、`priority`、`stakeholders` 已删除；`speaker` 必须填写人物本名，不加 `@`。

## 3. 顶层字段

| 字段 | 类型 | 必需 | 导入行为 |
| :--- | :--- | :---: | :--- |
| `scenarioPlan` | object | 否 | 数据集生成与评测元数据；`evalSampleId` 用于组成会话标题，其余内容不进入模型上下文 |
| `group` | object | 是 | 群组基础信息；至少需要 `groupName` |
| `users` | object[] | 建议 | 成员资料；缺失时允许导入，但成员展示会降级 |
| `relationships` | object[] | 否 | 组织或协作关系；缺失时关系图为空 |
| `messages` | object[] | 是 | 原始群聊消息，不能为空，且 `messageId` 必须唯一 |
| `groundTruth` | object | 否 | 人工评测标注；缺失时仍可分析，但不能进行黄金评测 |
| `qualityAudit` | object | 否 | 数据集生成质量记录，不进入模型上下文 |

## 4. scenarioPlan 字段

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `evalSampleId` | string | 样例编号；存在时会话标题显示为“群名（样例编号）” |
| `scenarioId` | string | 场景模板编号 |
| `representativeFocus` | string | 样例主要考查点 |
| `primaryBusinessScene` | string | 主业务场景 |
| `secondaryBusinessScene` | string | 次业务场景，可为空 |
| `targetMessageCount` | number | 计划消息数 |
| `timeSpan` | string | 计划时间范围 |
| `participantCount` | number | 计划参与人数 |
| `positionMix` | string[] | 计划职位构成 |
| `topicPlan` | object[] | 计划议题，通常包含 `topicId`、`theme` |
| `eventPlan` | object[] | 计划事件，通常包含 `eventSeed`、`plannedType`、`plannedLifecycle` |
| `noiseRatio` | number | 计划噪声比例，范围 0–1 |
| `styleMix` | string[] | 对话风格组合 |
| `technicalTextPlan` | object[] | 版本号、链接、命令等技术文本计划 |
| `datasetMode` | string | 如 `synthetic` 或 `real` |
| `goldenSummaryProvided` | boolean | 数据集侧声明；平台仍以实际 `groundTruth.goldenSummary` 为准 |
| `difficultyTags` | string[] | 难度标签 |

## 5. group 字段

| 字段 | 类型 | 必需 | 说明 |
| :--- | :--- | :---: | :--- |
| `groupId` | string | 建议 | 群组唯一编号 |
| `groupName` | string | 是 | 群组名称 |
| `groupType` | string | 否 | 部门群、项目群等 |
| `members` | string[] | 建议 | 成员 `userId` 列表 |
| `targetPeriod` | string | 否 | 会话目标周期 |
| `groupPurpose` | string | 否 | 群组用途 |

不再定义 `targetUser`。即使旧文件带有该字段，导入时也不会进入会话、模型上下文或页面。

## 6. users 字段

| 字段 | 类型 | 必需 | 说明 |
| :--- | :--- | :---: | :--- |
| `userId` | string | 是 | 成员唯一编号，与消息发送者和关系字段关联 |
| `employeeNo` | string | 否 | 工号 |
| `displayName` | string | 是 | 人物本名；重要消息的 `speaker` 必须与其完全一致 |
| `positionName` | string | 否 | 职位名称，仅用于成员信息展示 |
| `responsibilities` | string | 否 | 职责描述，不得作为补造事实的依据 |
| `rolePriors` | string | 否 | 技术栈或角色先验，不得作为补造事实的依据 |

## 7. relationships 字段

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `source` | string | 起点成员 `userId` |
| `target` | string | 终点成员 `userId` |
| `relationType` | string | 上下级、协作、汇报等关系类型 |
| `scope` | string | 关系适用范围 |

## 8. messages 字段

| 字段 | 类型 | 必需 | 说明 |
| :--- | :--- | :---: | :--- |
| `messageId` | string | 是 | 会话内唯一消息 ID；黄金重要消息通过该字段回指原文 |
| `sequenceNo` | number | 建议 | 消息顺序号 |
| `timestamp` | string | 建议 | ISO-8601 时间 |
| `senderUserId` | string | 建议 | 发送者 `userId` |
| `senderDisplayName` | string | 是 | 发送者本名，不加 `@` |
| `content` | string | 是 | 原始消息正文；正文中的 `@提及`必须保留 |
| `mentions` | string 或 string[] | 否 | 被提及人员；没有时可为空字符串或空数组 |
| `replyTo` | string 或 null | 否 | 被回复消息的 `messageId` |
| `messageType` | string | 否 | 文本、富文本、图片说明等消息类型 |

## 9. groundTruth.goldenSummary 字段

| 字段 | 类型 | 必需 | 说明 |
| :--- | :--- | :---: | :--- |
| `groupName` | string | 是 | 黄金简报群名 |
| `period` | string | 是 | 黄金简报周期 |
| `abstractPoints` | string[] | 是 | 三条核心摘要要点 |
| `decisions` | object[] | 是 | 决议数组；子字段为 `title`、`context`、`status` |
| `todos` | object[] | 是 | 待办数组；子字段为 `priority`、`task`、`owner`、`dueDate`、`status` |
| `topics` | object[] | 是 | 议题数组；子字段为 `title`、`timeRange`、`participants`、`process`、`conclusion` |
| `openIssues` | string[] | 是 | 未解决问题，没有时使用 `[]` |
| `keyInfo` | string[] | 是 | 文件、链接、命令、版本号等关键信息，没有时使用 `[]` |

摘要中的负责人、参与者和正文 `@提及`仍需原样保留 `@`。只有重要消息对象的 `speaker` 使用不带 `@` 的本名。

## 10. groundTruth.importantMessages 字段

`importantMessages` 必须与 `goldenSummary` 并列，不放在 `goldenSummary` 内部。

| 字段 | 类型 | 必需 | 校验规则 |
| :--- | :--- | :---: | :--- |
| `messageId` | string | 是 | 必须存在于当前文件的 `messages[].messageId` |
| `speaker` | string | 是 | 必须等于对应原消息的 `senderDisplayName`；只写本名，不加 `@` |
| `content` | string | 是 | 必须与对应原消息的 `content` 完全一致 |
| `reason` | string | 是 | 一句话解释业务重要性，建议不超过 25 字 |

以下字段已经删除，出现时导入预检失败：

- `type`
- `priority`
- `stakeholders`

标注语义：

- 已完整标注且确实没有重要消息：填写 `"importantMessages": []`；
- 尚未进行重要消息人工标注：省略整个 `importantMessages` 字段；
- 省略字段时，重要消息精确率和召回率显示“暂无标注”，不会记为 0；
- 同一说话人的消息在最终 Markdown 中归入同一个本名标题，例如 `#### 钱伟`；
- “重要消息”固定显示在整份 Markdown 的末尾。

## 11. groundTruth.eventLedger 与 qualityAudit

`groundTruth.eventLedger` 可保存人工事件账本，用于数据集审计；常见字段包括 `eventId`、`topicId`、`eventType`、`content`、`state`、`participants`、`owner`、`dueDate`、`evidenceMessageIds`、`relatedEventIds`、`supersedes` 和 `confidence`。当前导入不会把该账本直接提供给模型，防止黄金信息泄漏。

`qualityAudit` 可保存样例生成时的质量检查，包括 `pass`、`errors`、`warnings`、`coverage` 和 `rewriteInstructions`。该对象也不进入模型上下文。

## 12. 导入预检结果

导入弹窗会显示：

- 群名称；
- 消息数；
- 成员数；
- 角色数；
- 关系数；
- 黄金摘要是否携带；
- 重要消息是否已标注及标注条数。

以下情况会阻止导入：JSON 无法解析、缺少群名、消息数组为空、消息 ID 缺失或重复、数据集消息缺少 `senderDisplayName`、黄金重要消息使用已删除字段、`speaker` 带 `@` 或与原发送者不一致、`content` 与原文不一致、黄金重要消息缺少必需字段。
