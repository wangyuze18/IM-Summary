# 评测方案：摘要与重要消息双任务对比

## 1. 研究问题

在固定输入、固定模型绑定和固定黄金标注下，团队模式是否相对基础模式：

1. 提高摘要事实准确率、文本质量和关键信息覆盖；
2. 提高重要消息抽取精确率与召回率；
3. 通过共享证据、状态消歧和任务专属审核带来可解释增益。

团队模式被设计为有较大提升潜力，但项目不能在没有实验结果时宣称确定提升。最终结论必须报告均值、方差、样本数和显著性/置信区间。

## 2. 对比设置

### 基础模式

摘要模型和重要消息模型同时读取原始群聊，并行直出，无共享中间结果、无审核、无修订。

### 团队模式

事件识别 → 状态判断 → 共享证据账本 → 摘要/重要消息并行生成 → 两个任务独立审核 → 失败分支定向修订。

### 公平性控制

- 同一会话和消息顺序；
- 相同摘要生成模型等级；
- 两种模式共用重要消息模型绑定；
- 相同 temperature、超时和最大上下文策略；
- 不向任一生成流程提供黄金标注；
- 每个设置至少运行 3 个随机种子或重复次数；
- 记录 token、调用次数和耗时作为成本指标。

## 3. 黄金数据

每个样例至少包含原始消息和黄金摘要。要同时评测重要消息，在现有数据集的 `groundTruth` 下增加与 `goldenSummary` 并列的 `importantMessages`：

```json
{
  "groundTruth": {
    "goldenSummary": {
      "groupName": "群名",
      "period": "2026-08-17~2026-08-23",
      "abstractPoints": ["摘要要点1", "摘要要点2", "摘要要点3"],
      "decisions": [{"title":"决议","context":"背景","status":"已达成"}],
      "todos": [{"priority":"高","task":"动词+对象","owner":"@员工","dueDate":"截止日期","status":"待处理"}],
      "topics": [{"title":"议题","timeRange":"时间段","participants":"@甲, @乙","process":"过程","conclusion":"结论"}],
      "openIssues": [],
      "keyInfo": []
    },
    "importantMessages": [
      {
        "messageId": "m01",
        "speaker": "@甲",
        "content": "必须与原始消息一致",
        "type": "待办",
        "priority": "高",
        "stakeholders": ["执行-@乙"],
        "reason": "含明确负责人和截止时间"
      }
    ]
  }
}
```

字段名必须是 `groundTruth.importantMessages`，不使用 `goldenImportantMessages`。也允许把 `importantMessages` 放在 `goldenSummary` 对象内，但推荐使用上述并列结构，便于摘要评测与重要消息评测隔离。现有样例未补齐黄金重要消息时，只评摘要四项，重要消息精确率/召回率记为不可评，不得写成 0，也不能用模型自评代替人工黄金。

黄金重要消息建议由两名标注员独立选择并由第三人仲裁。messageId 是首选主键；同时标注 type、最终状态和允许的 stakeholder，以支持误差分析。

## 4. 六项主指标

| 任务 | 指标 | 趋势 | 定义 |
| :--- | :--- | :---: | :--- |
| 摘要 | 摘要准确率 | ↑ | 生成摘要中有证据或黄金支撑的事实陈述比例 |
| 摘要 | 关键信息遗漏率 | ↓ | 黄金关键信息点未被生成摘要覆盖的比例 |
| 摘要 | 文本相似度 | ↑ | 规范化摘要主体与黄金摘要的 ROUGE-L |
| 摘要 | 大模型文本评分 | ↑ | 0–100，综合忠实、完整、结构与精炼度 |
| 重要消息 | 精确率 | ↑ | 正确匹配条目数 / 生成条目数 |
| 重要消息 | 召回率 | ↑ | 正确匹配条目数 / 黄金条目数 |

页面将六项指标放在同一行，下方历史表格也保留六列。`llm_score` 只评价摘要，绝不评价重要消息。

## 5. 计算流程

### 5.1 摘要隔离

后端从生成结构中移除 `importantMessages`，渲染剩余摘要字段。摘要判官只接收生成摘要主体与黄金摘要，输出 accuracy、omission rate 和 `llm_score`。

文本相似度先移除模式标签与 Markdown 标记，再以中文字符、英文/数字词为 token 计算 LCS F1，即 ROUGE-L。

### 5.2 重要消息匹配

首选 messageId 精确匹配。缺少 ID 时才按 speaker、原文语义、类型和最终状态综合匹配。以下属于假阳性：

- 寒暄或普通讨论；
- 虚构/合并的原文；
- 已被覆盖的旧状态；
- 重复抽取；
- 没有依据的人员相关性。

遗漏明确待办、决议、风险、审批、阻断或关键进度属于假阴性。

## 6. 贡献分析

除基础/团队总对比外，执行消融实验：

| 试验 | 目的 | 主要观察指标 |
| :--- | :--- | :--- |
| + 事件证据 | 衡量结构化证据贡献 | 摘要遗漏率、消息召回率 |
| + 状态判断 | 衡量新旧状态消歧 | 摘要准确率、消息精确率 |
| + 摘要审核 | 衡量摘要纠错 | 准确率、遗漏率、LLM 分 |
| + 消息审核 | 衡量抽取纠错 | 消息精确率、召回率 |
| 完整团队模式 | 衡量组合效果 | 全部六项 |

还应按错误类型报告：提议误判决议、负责人脑补、日期/版本实体错误、过时状态、重要消息假阳性、重要消息遗漏和原文改写。

## 8. 成功判据

“较大提升”应在实验前定义，避免事后选择。建议至少满足：

- 摘要准确率与 LLM 分显著上升，遗漏率显著下降；
- 重要消息精确率、召回率均不下降，至少一项具有明显绝对提升；
- 增益在多数会话而非少数长会话上出现；
- 成本和延迟增长被单独披露；
- 定向修订相对全流程重跑节约调用且不损害质量。

具体阈值应依据验证集难度预注册，例如主要指标绝对提升不少于 5 个百分点，并给出置信区间。

## 9. 历史与过期

每次评测绑定 `summaryId`、摘要版本、黄金版本和模式。新摘要产生后，旧记录标记为过期但保留在历史表格中。导出文件必须包含六项指标、模式、版本、时间和有效状态，以支持论文复现。
